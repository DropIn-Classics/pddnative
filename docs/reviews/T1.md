# Review of T1 (branch `muse/T1-ddpcintr` at 7b836f8)

Checked from the main checkout: only the three files the task names
changed; the branch's hints build IDENTICAL (1178 instructions, 161
labels, 1 as DB); `gaps.py` leaves the 6 zero gaps the notes list;
`cv4.py --hints` prints exactly the 155 names in the hints. cv4.py

one entry point is written as `code` where the pointer is known. Fix

## Must fix

1. **paltable holds words, not bytes.** The notes read it as a table of
   byte indices ("offsets/0100h") and say it is 16 bytes long. Read it as
   words: it holds four near offsets into PALSEG, the offsets of the four
   palettes (the debug SegMap size 0C08 gives 8 bytes; the rest is
   padding up to DATA). disply_pics loads SI with its offset (`LEA SI` at
   CODE:006C) and reads `MOV DI,ES:[SI]` with ES=PALSEG, then passes
   ES:DI to fadeup/fadedn. Add `words PALSEG:0C00 4 PALSEG` with a
   comment saying so. I checked it: still IDENTICAL, and griflogo,
   spiderlogo, presents and titl then appear (165 labels). Rewrite the
   notes' PALSEG paragraph from this.

2. **delaytable: BX is not always 0.** The notes say BX=0 at CODE:008F
   and call it "verified". But disply_pics_aa runs three times, and
   each pass ends with `ADD BX,2`. So `[BX+delaytable]` reads one word
   per picture, the number of frames the picture stays up (the
   disply_pics_bb loop counts CX down with `waitframe 1`; a key jumps to
   disply_pics_dp020 and ends the whole show). Correct the notes and the
   comment on the `raw` hint.

3. **kbdint is reached through a pointer; say which.** setkbdint passes
   it to INT 21h AH=25h as `MOV DX,51DH` at CODE:04FD. Replace
   `code CODE:051D` with `ptr CODE:04FD CODE` and a comment (the INT 9
   vector set in setkbdint). I checked it: IDENTICAL, and the line
   becomes `MOV DX,OFFSET kbdint`. ptrscan found nothing because you ran
   it after the `code` hints had already made kbdint reached. Run
   ptrscan on a copy of the hints without the `code` lines to see
   whether it finds any other pointer.

4. **Wrong routine comments.** Check each comment against the
   disassembly again. Three wrong ones I found:
   - CODE:0000: intro does not call DoPlayTrack (disply_pics does). It
     calls mstart2, getcmdline, malloc, init320200, setkbdint,
     load_pics, mfree and disply_pics, then falls through into ldfail.
   - CODE:051D: kbdint does not touch vblfl. It stores the scan code in
     lastscan (E0-prefixed codes with bit 7 set, fake shifts 2Ah/36h
     after E0 dropped) and sets or clears that code's bit in kmat
     (32 bytes, one bit per code).
   - CODE:0949: malloc takes the paragraph count in AX, not BX. On
     failure AX holds the largest block DOS offers (the BX from INT 21h).

   While you are at it: nothing in this program writes musfl or sets
   vblfl (wblnk only clears vblfl and then waits on it), so wblnk
   presumably always polls port 3DAh. Say this in wblnk's comment as
   something the code shows, not a guess.

5. **No game bytes in the notes (AGENTS.md rule 3).** The delaytable
   paragraph copies its bytes, and the paltable paragraph lists its
   values. Describe what a table holds (a word per picture, a count of
   frames). Do not copy the values.

6. **"What the program does" is not step by step.** It reads as a list
   of every routine. Rewrite it in a few numbered steps in the order the
   code runs: shrink memory; read the CD track number from the command
   line; allocate the picture buffer; Mode X 320x200 and the keyboard
   handler; load the four pictures and copy each into its own VRAM page
   (pages 3E80h apart); free the buffer; start the track; show three
   pictures, each faded up, held for its delaytable time, then faded
   down (a key skips to the end); show the fourth until a key or until
   GetQInfo stops returning 2 (presumably: the track has ended); fade
   down, stop the track, restore INT 9, exit.
   Check each step against the code before you write it.

7. **Say which routines the program never calls.** Without the `code`
   hints, these routines are not reached from the entry point:
   scrload, rasplit, setpal, clvram, wrmd0, wrmd1, vdispoff, vdispon,
   init320240, getpal, wkeyend, wkeypress, clrkey, f_save, fld2vram,
   mv2vram, GetTrackInfo and mstart (kbdint only through its pointer,
   see 3). I got this list from `gaps.py` on the hints with the `code`
   lines removed, so check it the same way. Keep their `code` hints (the
   debug information shows they are routines). Mark them in the hints

9. cv4.py: in CV4 the 16-bit records are S_LDATA16 0101, S_GDATA16

   one each of 0001, 0005 and 0009) so nothing is dropped without a
   trace. None of this changes DDPCINTR's output. It matters for the
   next program. Also fix the docstrings of `find_cv` ("(base, )") and
   `segmap` (it returns only the descriptors).
