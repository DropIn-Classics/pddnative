The user gave the task to Claude (Sol was not ready). Worked directly on

## What was made

- `port/src/textmode.c`, `textmode.h`: an 80x25 text screen (character
  and attribute per cell, the 16 CGA colours) drawn into a 640x400
  picture. The font is our own: printable ASCII drawn as 8x16 bitmaps in
  the source (twelve bands of eight characters, `#` a pixel), the line,
  box, shade and arrow characters of code page 437 built by rules under
  their code page numbers. Nothing from a VGA BIOS or the game's files.
- `port/src/launcher.c`, `launcher.h`: the setup screen (pages: main,
  play a table, game options, sound and window), `DDPCOPTN.BIN` read and
  written, `pdd.cfg` read, applied and written.
- `port/src/main.c`: without `-prog`/`-table` and with a window, the
  launcher; a table chosen there is loaded (`mem_load`) and run
  (`pd_run`); when it returns (Esc, Y) the music is stopped (`snd_stop`),
  the settings saved, and the launcher shown again. An error in a table
  is shown in a box on the launcher instead of ending the program.
- Beyond the files the task named (the lead's call): `platform.h` and the
  three platforms (`plat_has_window`, `plat_set_fullscreen`,
  `plat_fullscreen`), `hud.c`/`hud.h` (`hud_set`, `hud_get`).

## Facts used, and where they come from

- The F10 screen's ranges: the hit-box table at DDPCMAIN's OPTIONS:0009
  (a count, then 10-byte records: x1 y1 x2 y2, the current value, the
  highest; CODE:15E9 steps the value from 1 to the highest). Balls,
  music and colours 1-2, table angle 1-3, resolution 1-2; records 5-7
  are "define keys", "save" and "exit" (CODE:1681: indexes 4, 5, 6).
  Its texts: "Number of balls", "In-game music on or off", "In-game screen
  mode", "Table angle", "Define game keys", "Select game resolution".
  Read, not run.
- What the values do in the table: `load_options` (balls 1: 3, else 5),
  `timer_callback` (music other than 1: only `play_tune`, the main
  tune), `grey_palettes` (palette 1: grey), gravity 9 + 2 * (slope - 1),
  `opt_screen` (docs/HANDOFF.md).
- The key words: key_map's byte, then the bit as a mask
  (`tools/pdfiles.py`, `pd_ball.c`). Keys the table reads itself: Esc
  and F1-F8 (`read_game_keys`), P (`st_play`: key_map byte 3 bit 1), Y
  and N only in the quit question (allowed as game keys).
- The eighth table's name: SELECT.VGA (`tools/gfxfiles.py`, F7) shows
  "Revenge of the Robot Warriors".
- The engine keeps no state in C statics besides `pd_main.c`'s exit
  (grep over `port/src`), so a table after another starts from
  `mem_load`'s fresh memory.

it (the ISO 9660 walk of `tools/gogx.py`, checked names, the image must
hold DREAMS1\PD.EXE, into `game.part` then renamed). `main.c`: a folder
counts as the game's only with a DREAMS1 in it; the data folder's `game`
is a third place looked in; `-gog FILE`. The launcher's screen for it:
the image found and where it goes, "Copy the files" or "Quit", a
progress bar, the reason when it failed; when nothing is found, how to
give the files.

working directory without `game/`: the image in `/Applications/Pinball
Dreams Deluxe.app` found, 241 files copied, `diff -r` against `game/`
from `gogx.py`: identical; then Steel Wheel started from the copy. A
file that is no CD image given with `-gog`: "The image holds no CD file
system." and nothing left behind. Not checked: the Windows places (the
