# T7: history viewer data files

Branch `sol/T7-history`. Files: `src/DDPCMAIN.hints`,
`tools/ddfiles.py`, and this notes file.

The task was to trace every file opened by DDPCMAIN's F9 history viewer,
document the formats in the hints, and implement parsers, identical
round-trip encoders, and PNG previews for the five language pairs,
HISTORY.FNT, and the picture files actually used by the viewer.

## Viewer file path

These findings are read from DDPCMAIN and checked against the files, not
checked by running the viewer:

- The F9 language picker runs immediately before `history_screen`; it
  loads `DDPCLANG.VGA` from DELUXE. `history_screen` changes to
  `..\HISTORY` in `history_init` and loads `DDPCHIST.VGA` through
  `load_vga_image`.
- `load_history_font` reads `HISTORY.FNT`. `load_history_idx` selects
  one of the five `.IDX` names through `language_index`; entering the
  table browser makes `load_history_hop` select the matching `.HOP`.
- A nine-byte internal table record selects the `.IDX` record and one
  or two embedded picture-name offsets. In VGA mode the selected `.016`
  goes to `load_history_picture_16`. When VESA mode 101h is available,
  `select_history_picture_format` changes every embedded extension from
  `.016` to `.256` in place and `load_history_picture_256` reads it.
- The program enumerates no directory. Its 53 table records contain 75
  picture slots but 74 distinct names: Monte Carlo uses the same name
  for both slots. Those names match all 74 `.016` files exactly, and
  the derived names match all 74 `.256` files exactly; neither set has
  a missing or extra file.

The other files in HISTORY are not opened by this path:

- `BIGBRAVE.025` and `LIZARD_1.1` have no embedded name or table-record
  reference.
- `CLRFILE.CV4` has no reference.
- `INTRO2.MOD` has a string in `intro_module_table`, but the only
  reachable call of `load_sound` passes index 0 (`INTRO.MOD`) during
  main-menu initialization. No call passes index 1.

## Formats and tool

`tools/ddfiles.py` has four subcommands, each of which parses and then
encodes the result and requires byte-for-byte identity:

- `idx FILE`: 53 little-endian five-byte records. Fields are the HOP
  record's start offset, the offset of its `@` end marker (not read by
  the viewer), and the number of displayed strings minus one. The first
  byte of DDPCMAIN's nine-byte table record selects this record number.
  When the sibling HOP is present, the command prints the linked title.
- `hop FILE`: uses the sibling IDX to decode the 53 records. Each record
  contains double-NUL-terminated screen strings; CR/LF after a string
  adds a blank display row. Records are physically in a different order
  from their IDs and are separated by an `@` marker. Text bytes index
  the font directly; terminal output uses CP437 as the closest mapping.
- `font FILE [--png OUT]`: 2,048 bytes, 256 glyphs, eight row bytes per
  glyph, most-significant bit at the left. The PNG is a 16 by 16 glyph
  sheet.
- `picture FILE [--png OUT]`: `.016` is four consecutive VGA bit planes
  of 38,400 bytes (80 bytes per row by 480 rows), producing 640x480
  16-colour pixels. `.256` is a 768-byte VGA DAC palette (components
  0..63) followed by 640x480 pixel indices. The command also accepts
  `DDPCHIST.VGA`, 320x200 raw pixel indices; its palette is embedded in
  DDPCMAIN, so the standalone preview is greyscale.

All language files round-trip exactly:

| language | HOP bytes | IDX bytes | displayed strings | stored strings |
|---|---:|---:|---:|---:|
| English | 56,970 | 265 | 1,762 | 1,763 |
| French | 60,463 | 265 | 1,853 | 1,853 |
| German | 64,763 | 265 | 1,986 | 1,987 |
| Italian | 61,617 | 265 | 1,871 | 1,871 |
| Spanish | 65,265 | 265 | 1,984 | 1,985 |

The count differences are in the shipped data, not discarded by the
parser: English record 40, German record 50, and Spanish record 51 each
store one final string beyond the IDX display count. `hop` labels those
strings `[not displayed]`, and its encoder retains them. Record 0 was
printed in English and German; its title, metadata, and prose are
readable in both.

All 74 `.016` and all 74 `.256` files parse to their last byte and
round-trip identically. So do HISTORY.FNT and DDPCHIST.VGA.

## Visual checks

## Hints

`src/DDPCMAIN.hints` now names and comments the font, HOP, IDX and both
picture loaders, their copy/render helpers, format selection, table
display and next-picture routines. The resource and state comments give
the complete table-record fields and the loaded IDX/HOP layouts. The
generated DDPCMAIN remains identical.

## Verification

`python -m py_compile tools/ddfiles.py` succeeds. All five IDX/HOP pairs,
the font, DDPCHIST.VGA, 74 `.016` files and 74 `.256` files were parsed
and re-encoded identically. The English/German text and generated PNGs
listed above were inspected. `git diff --check` succeeds and
`python tools/check.py` says `all ok`.

`tools/run` was not used: the claims about which routines open or ignore
files and how the bytes are consumed are from the disassembly; the file
layouts and encoders are checked directly against every applicable file.
