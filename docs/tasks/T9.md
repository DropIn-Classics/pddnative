# T9: FLI animations

Added `tools/flifiles.py`.  It reads the 128-byte Autodesk Animator FLI
header (AF11h), every F1FAh frame and every chunk, decodes COLOR_64, LC,
BLACK, BRUN and COPY chunks, and writes a selected zero-based displayed
frame as an indexed PNG.  The six-bit chunk palette is used directly; no
game bytes are kept in the tool.  Its encoder preserves the parsed chunk
representation rather than recompressing pixels.

## Files

Every file has one more physical frame chunk than the displayed frame count
in its header.  Decoding that final chunk after the last displayed frame
produces exactly frame 0 again, pixels and palette, so all twelve have a ring
frame.  All frames decoded without error, every chunk consumed its data, all
files parsed to their last byte, and all encoded again to identical bytes.

| file | displayed + ring frames | speed | chunk counts |
|---|---:|---:|---|
| BEATBOX.FLI | 201 + 1 | 3 | COLOR_64 1, LC 200, BRUN 1 |
| IGNITION.FLI | 201 + 1 | 3 | COLOR_64 1, LC 201, BRUN 1 |
| INTRO_P1.FLI | 232 + 1 | 5 | COLOR_64 1, LC 218, BRUN 1 |
| INTRO_P2.FLI | 138 + 1 | 4 | COLOR_64 1, LC 127, BRUN 1 |

The speed is the header word in 1/70-second FLI jiffies.  Some frames have no
chunks and leave the previous picture unchanged.  Seven final chunks declare
one byte more than is physically present before the next frame: their even
size includes a zero pad byte that the file omits at the frame boundary.  The
parser accepts exactly that one-byte final-chunk case, preserves the declared
size for the identical encoder, and otherwise requires every declared chunk
to fit.

## DDFLIPLY.EXE

Read from the program, not run.  The main routine at `0188:0006` reads the
first non-space command-tail character, subtracts `0`, and uses the following
tables in segment 01F5h:

| argument | animation |
|---:|---|
| 0 | SPIN21ST.FLI, INTRO_P1.FLI, INTRO_P2.FLI, INTRO_P3.FLI in sequence |
| 1 | IGNITION.FLI |
| 2 | STEELWHL.FLI |
| 3 | BEATBOX.FLI |
| 4 | NIGHTMRE.FLI |
| 5 | NEPTUNE.FLI |
| 6 | SAFARI.FLI |
| 7 | REVENGE.FLI |
| 8 | STALLTRN.FLI |

There is no range check or fallback for another character: a value above 8
indexes beyond the eight-entry table, while a missing character or one below
`0` leaves an unrelated value in BL.  Those inputs do not deliberately select
an animation.

The wrapper at `01F0:0028` passes -1 as the speed override.  The player at
`01A5:000B` therefore reads the FLI header word at offset 10h, multiplies it
by 41h, and waits for that many clock units between frames.  `0000:0264`
programs PIT channel 0 with divisor 0, and `0000:026F` combines the BIOS tick
with the high byte of the latched PIT count: 256 clock units per BIOS tick.
Thus 41h clock units approximate one 1/70-second FLI jiffy.  The callback
stops at the header's displayed frame count, so the extra ring frame is not
shown during this one-shot playback.
