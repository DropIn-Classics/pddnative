## Formats and tool

`tools/gfxfiles.py FILE [--png OUT] [--table EXT]` selects the format
from the file name, parses it, encodes it again, and requires identical
bytes. It extracts VGA DAC values directly from the applicable shipped
program. No palette bytes are in the repository.

- The VGA pictures are raw, eight-bit, 320 pixels wide. Six are 320x200
  (64,000 bytes). `SELECT.VGA` is one 320x790 scrolling picture
  (252,800 bytes); `load_vga_image` reads it in chunks and appends each
  chunk in Mode X video memory.
- Every `TABLE2M` is raw 320x512, eight-bit pixels (163,840 bytes).
  Its preview reconstructs all 256 DAC entries as the applicable program
  does. For PD this includes the black fill, both repetitions of source
  colours 0..3Fh, and the default-colour FEh/FFh values. For PD2 it uses
  the whole 300h-byte source and applies `make_off_colours` to 40h..7Fh.
  Table and flipper previews show the default `opt_palette` value 2
  (colour); they do not apply `grey_palettes` for value 1.
- An SPR begins with a table of little-endian record offsets. Each
  record has width and height words, then `width * height` indexed
  pixels; bytes through the next offset are retained as record padding.
  `DDPCICON.SPR` has 15 records: one 16x16 mouse cursor and fourteen
  48x24 option icons. The cursor treats index 0 as transparent; the
  option-icon copier is opaque.
- Both `FLIPPERS.SPR` files have ten records: four 49x29, four 52x21,
  and two 52x15 frames. PD's file has no padding. PD2's has 1,268 zero
  padding bytes in total (203 after each 49x29 record, 84 after each
  52x21, and 60 after each 52x15); its reader uses only the declared
  pixel count. Index 0 is transparent. Because each file serves four
  differently coloured tables, `--table EXT` selects the PNG palette;
  it defaults to `IGN` or `UND`.

All seven DELUXE VGA pictures, all three physical SPR files, and all
eight TABLE2M files parse to their last byte and round-trip identically.

## Visual checks

The generated PNGs are ignored and were not committed:

- `DDPCBKGD.VGA.png` is the complete 320x200 dark blue options-screen
  texture with its OPTIONS palette.
- `FLIPPERS.SPR.png`, with Ignition's palette, shows ten clean red and
  white flipper positions with transparent surroundings.
- `TABLE2M.IGN.png` is the complete 320x512 Ignition table, including
  its playfield artwork and bottom display area in the expected colours.
- As additional checks, `SELECT.VGA.png` is the complete vertical menu
  strip from F1 through the configuration and high-score areas, and
  `DDPCICON.SPR.png` shows the mouse cursor and fourteen readable option
  icons.

The corrected table palettes were also compared with screenshots from the
original programs, run with SBLASTER.SDR. The comparison aligned the first
160 screenshot rows with the raw table preview and allowed one 8-bit RGB
step because the runner expands six-bit DAC values by bit replication while
the PNG tool rounds them to 0..255:

- Beat Box (PD, table 2), at 8 seconds, aligned at table row 71: all 51,200
  pixels agree within one step, including all 50 pixels whose raw indices
  are C4h or D2h..D5h.
- Neptune (PD2, table 0), at 4 seconds, aligned at table row 175: all 14,080
  pixels using the 38 visible indices C0h or above agree within one step.
  Overall 49,569 of 51,200 pixels agree; every remaining pixel uses a live
  lamp index from 49h through 70h, whose palette the running idle display
  has changed from the preview's initially-off values.

## Verification

`python -m py_compile tools/gfxfiles.py` succeeds. DDPCINTR and
DDPCMAIN rebuild IDENTICAL after the hint changes. With `PDD_GAME` set
to the unpacked installed game, `python tools/check.py` says `all ok`.

`tools/run` was used for the two palette comparisons above. Which routines
open and consume the files, and how they install the palettes, was read from
the disassembly. File dimensions, record layouts, palette ranges and
round-trip encoders were checked directly against every applicable shipped
file.
