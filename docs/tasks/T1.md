# T1: DDPCINTR.EXE, stage 1 with names

Branch `muse/T1-ddpcintr`. Files: `src/DDPCINTR.hints` (new),
`tools/cv4.py` (new), this notes file.

## Findings

- DDPCINTR.EXE: file 19332 bytes, image 6886 (header 512, `SS:SP=01AF:0800`,
  `CS:IP=0000:0000`), tail 11934 bytes CodeView NB08. 25 relocs, all in
  CODE. Starting point from TASKS.md builds IDENTICAL (689 instructions,
  104 labels, 1 as DB); `gaps.py` shows 11 gaps, 940 of 2416 CODE bytes
  not reached (baseline).
- Segments (frames): CODE 0000 (2416 bytes), PALSEG 0097 (3088, four
  768-byte palettes: `griflogo`, `spiderlogo`, `presents`, `titl` at
  0000/0300/0600/0900 plus `paltable` at 0C00), DATA 0158 (1392),
  STACK 01AF (2048, `size=800`). Debug SegMap says CODE 0000 size 0970,
  PALSEG 0097 size 0C08, VARIABLES 0158 size 0566, USTACK 01AF size 0800
  (a few bytes less than the hints sizes: trailing zeros). Mapping debug
  seg index -> hints by frame: 1->CODE, 2->PALSEG, 3->DATA, 4->STACK,
  5 dummy (empty, `screen` skipped). Kept hints DATA (not VARIABLES) and
  STACK (not USTACK): the tools require DATA (ASSUME, DS tracking);
  PALSEG keeps class FAR_DATA (accessed via ES, like PD's TDATA; debug
  says class DATA). Checked a few by disassembly: `getcmdline` at
  CODE:01F0 sits on a `PUSHA` procedure, `fadedn` at CODE:03EA on a fade
  routine, `kbdint` at CODE:051D starts with `CLI`, etc.
- CodeView tail: first NB08 at file offset 0x1CE8 (tail+2), footer NB08
  at end with dword 0x2E9C (size from first NB08 to EOF). Directory at
  base+0x2E0C: 10 entries (sstModule x2, sstAlignSym, sstSrcModule,
  sstGlobalPub, sstGlobalSym(empty), sstLibraries(empty), sstMPC,
  sstSegMap, sstSegName). AlignSym (76, 3928 bytes) holds 44 PROCs
  (0105), data (0101), code labels (0109), ENDs (0006); 200 records
  total. Publics (10072, 1502 bytes: 16 header + 1036 symbols + 450 hash)
  holds 52 publics (0103), all CODE seg 1 except `_end`/`__end`/`_edata`/
  `__edata` (seg 0, absolute, skipped for hints). `screen` (seg 5, dummy)
  skipped. `CODE:003E` has two names (`ldfail`, `exit`); kept `ldfail`,
  `exit` as a commented alias.
- `tools/cv4.py HINTS [--hints]` implemented (see its docstring for the
  NB08 layout). Default lists segments and symbols; `--hints` prints
  `name` hints (locals as `<routine>_<local>` without `@@`, e.g.
  `fadedn_fd_01`; `@L20` -> `GetSNL_L20`; `@@Again` in two routines ->
  `GetDiskInfo_Again`, `GetStartSec_Again`). 153 symbols + 52 publics
  -> 155 names: 44 PROC/public duplicates (same address+name, silent),
  4 absolute (`_end` etc., seg 0) skipped, 1 dummy (`screen`, seg 5)
  skipped, 1 alias (`exit` at CODE:003E, kept `ldfail`) commented.

## Remaining gaps (all data, zeros)

`gaps.py src/DDPCINTR.hints` (CODE, 2416 bytes): 6 gaps, 24 bytes.

- 0049-004B (2, `picmem`): CS WORD, zeros. Set at CODE:0023
  (`MOV CS:[0049],AX`) and read at CODE:0129/0030 (load segment for
  fload/scrload, presumably).
- 015D-015F (2, `scr`): CS WORD, zeros. Cleared at CODE:010D
  (`MOV CS:[015D],0` in load_pics).
- 057C-057D (1, `prefix`): CS BYTE, zeros. E0 prefix flag for kbdint
  (set at CODE:052D, tested at 0538).
- 069D-06A3 (6, `fhand`): three CS WORDs, zeros: `fhand` 069D (file
  handle from f_save at 0636), `fhigh` 069F (BX from f_save caller at
  0622), `flow` 06A1 (AX from caller at 0627).
- 0703-0705 (2, `membuf`): CS WORD, zeros. Segment from fld2vram's
  malloc at 06B8 (`MOV CS:[0703],AX`).
- 0925-0930 (11, no label): zeros. Inter-module padding: ddpcintr.obj
  covers CODE 0000-0924 (2341 bytes), ddpcmem.obj covers 0930-096F
  (64 bytes: mstart/malloc/mfree/msize); 0925-092F is 11 zero bytes
  between them.

## Names that do not appear (6 of 155)

`check_names` (hints names vs analysis labels): 149/155 appear; 6 do
not, all data with no direct refs found (indexed/computed access only,
verified by searching immediates/disps; presumably accessed as below,
not checked in full).

- DATA:003A `delaytable` (8 bytes: D8 00 D8 00 90 00 D8 00 ...): read at
  CODE:008F via `[BX+3A]` with BX=0 (via XOR BX,BX at 0076 and
  PUSHA/POPA; verified). No disp ref (analysis skips disp<0100h with
  reg). No `words`/`ptr` applies honestly.
- PALSEG:0000 `griflogo`, 0300 `spiderlogo`, 0600 `presents`, 0900 `titl`
  (768 bytes each), 0C00 `paltable` (16 bytes: 0000,0003,0006,0009... =
  palette indices, i.e. offsets/0100h): palettes for the four VGA
  pictures (names match DELUXE/*.VGA: 21STLOGO/SPIDER/PRESENTS/TITLE).
  No disp refs to PALSEG at all; immediates 0300 are CX counts (768),
  SI=0/DI=0 are VGA A000:0000 (verified, ES=A000h there). Palettes are
  presumably accessed via ES:SI with SI computed from paltable indices
  (index*0100h), e.g. LEA SI,[0C00] at CODE:006C loads paltable offset
  (intended PALSEG, but analysis defaults to DS=DATA and skips as out
  of range; no honest `ptr` for LEA disp). `ptrscan` finds none.

Also skipped (not in hints, documented): `screen` (seg 5 dummy),
`_end`/`__end`/`_edata`/`__edata` (seg 0 absolute).

## What the program does (from the code, step by step)

Intro (CODE:0000): sets DS/ES=DATA, mstart2 shrinks memory, INT 21h
AH=62h gets PSP, getcmdline parses digit, malloc 0FA1h paragraphs,
DoPlayTrack starts CD audio, disply_pics shows pictures with fades
(fadedn/fadeup via currentpal, setpal/getpal via 3C8/3C9), load_pics
loads four VGA files (introfnames table -> n1-n4 strings) via fload/
scrload into picmem/membuf and copies to VGA Mode X (init320200/
init320240, mvscr/mv2vram via srdwr, wrmd0/wrmd1, rasplit, setst,
vdispon/vdispoff, clvram, waitframe via wblnk), keyboard via kbdint
(INT 9, [kmat], [prefix]) with wkeyend/wkeypress/chkkey/clrkey,
CD audio via MSCDEX INT 2Fh (GetDiskInfo/GetTrackInfo/GetStartSec/
GetStartLen/GetQInfo/GetVolumeSize/DoStopTrack using [RequestBlock],
[Taddr], [drivenumber], [SNLTab], [PlayTrack] etc.), file I/O via DOS
3Dh/3Fh/3Ch (fload/f_save/fld2vram), tiny malloc/mfree/msize/mstart
via INT 21h AH=48h/49h/4Ah, then DoStopTrack, rstkbdint and INT 21h
AH=4Ch exit (CODE:003E ldfail/exit, reached by fallthrough and jumps
on failures). Nothing was checked by running; all jobs above use
presumably where inferred from INTs/ports/names (see `comment` hints).
