## Review answers (docs/reviews/T1.md at 7b836f8)

1. Paltable holds words, not bytes. `words PALSEG:0C00 4 PALSEG` added
   (disply_pics loads SI with its offset via LEA SI at CODE:006C and
   reads MOV DI,ES:[SI] with ES=PALSEG, then passes ES:DI to
   fadeup/fadedn). Still IDENTICAL; griflogo, spiderlogo, presents,
   titl now appear (165 labels). Notes rewritten from this: paltable is
   a table of four near offsets into PALSEG, the offsets of the four
   palettes; the debug SegMap size gives 8 bytes (four words); the rest
   is padding up to DATA. No values copied.
2. Delaytable: BX is not always 0. disply_pics_aa runs three times, each
   pass ends with ADD BX,2, so `[BX+delaytable]` at CODE:008F reads one
   word per picture, the number of frames the picture stays up (the
   disply_pics_bb loop counts CX down with `waitframe 1`; a key jumps to
   disply_pics_dp020 and ends the show). Notes and the `raw` comment
   corrected; no values copied (a word per picture, a count of frames).
3. kbdint is reached through a pointer. setkbdint passes it to INT 21h
   AH=25h as MOV DX at CODE:04FD. Replaced `code CODE:051D` with
   `ptr CODE:04FD CODE` and a comment (the INT 9 vector set in
   setkbdint). Still IDENTICAL; the line becomes MOV DX,OFFSET kbdint.
   ptrscan on a copy without `code` lines finds 0 candidates, same as
   with them; kbdint's pointer is an INT vector parameter (DX for
   AH=25h), not a base/index register, so ptrscan correctly ignores it.
4. Wrong routine comments fixed against the disassembly: intro calls
   mstart2, getcmdline, malloc, init320200, setkbdint, load_pics, mfree
   and disply_pics, then falls through into ldfail (not DoPlayTrack;
   disply_pics calls that). kbdint stores the scan code in lastscan
   (E0-prefixed codes with bit 7 set, fake shifts after E0 dropped) and
   sets or clears that code's bit in kmat (32 bytes, one bit per code);
   it does not touch vblfl. malloc takes the paragraph count in AX, not
   BX; on failure AX holds the largest block DOS offers (the BX from
   INT 21h). wblnk's comment now says what the code shows: nothing in
   this program writes musfl or sets vblfl (wblnk only clears vblfl and
   then waits on it), so it presumably always polls port 3DAh.
5. No game bytes in notes or hints comments. The delaytable and paltable
   paragraphs describe counts (a word per picture; four near offsets)
   without copying values. The `words` comment for introfnames no longer
   lists values.
6. What the program does, rewritten below as numbered steps in code

7. Routines never called (verified via `gaps.py` on a copy with `code`

## What the program does (checked against the code)

1. Shrink memory (mstart2 via msize: ES=CS-10h to DX paragraphs).
2. Read the CD track number from the command line (getcmdline parses
   the PSP digit).
3. Allocate the picture buffer (malloc).
4. Set Mode X 320x200 (init320200) and install the keyboard handler
   (setkbdint sets INT 9 to kbdint).
5. Load the four pictures (load_pics via introfnames and fload/scrload
   into picmem) and copy each into its own VRAM page (mvscr/mv2vram via
   srdwr; pages 3E80h apart via [scrst] and CS:[scr]).
6. Free the buffer (mfree).
7. Start the track (DoPlayTrack via GetStartLen and MSCDEX INT 2Fh).
8. Show three pictures, each faded up (fadeup), held for its delaytable
   time (disply_pics_bb loop with waitframe 1), then faded down
   (fadedn); a key jumps to disply_pics_dp020 and ends the whole show.
9. Show the fourth until a key or until GetQInfo stops returning 2
   (presumably: the track has ended).
10. Fade down, stop the track (DoStopTrack), restore INT 9 (rstkbdint),
    exit via ldfail (INT 21h AH=4Ch).

Nothing was checked by running; jobs marked presumably in the `comment`
hints are inferred from INTs/ports/names.
