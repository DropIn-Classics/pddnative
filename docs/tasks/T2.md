# T2: DDPCMAIN.EXE, stage 1

Branch `muse/T2-ddpcmain`. Files: `src/DDPCMAIN.hints`, this notes file.

## Result

DDPCMAIN.EXE is reproduced byte for byte from the generated source. The
final build has 5338 instructions, 908 labels and one instruction written
as DB (the original's `38 E2` form at CODE:05B1). `gaps.py` leaves 26
gaps / 5013 bytes, all data as listed below. `ptrscan.py` finds no
candidates. `tools/check.py` says `all ok`.

The program image is 58381 bytes (file 59405 bytes, no tail). Entry is
CODE:0000; SS:SP is 0E41:0800. The relocation frames and their meanings
are:

- CODE 0000 (17536 bytes).
- DATA 0448: ordinary menu data; DS and ES are initialized to it.
- FONTS 0766 (3F80h bytes): menu and option glyph bitmaps. CODE:05D4 and
  0792 read its 8-by-10 glyphs; DATA:1233 points to FONTS:2580 for the
  option text renderer at CODE:2E89.
- OPTIONS 0B5E (640h bytes): F10 UI records, texts, palettes, state and
  the `DDPCOPTN.BIN` path/data.
- HISTORY 0BC2 (27F0h bytes): F9 viewer file names, text/index data,
  state and buffers.
- STACK 0E41, 800h bytes.

Relocation sites are ordered DATA then CODE. The relocation values occur
at 85 DATA, 37 HISTORY, 28 OPTIONS, 3 FONTS and 3 CODE sites.

## What the program does

From the disassembly (not run):

1. `start` (CODE:0000) resizes/checks DOS memory, installs its INT 9
   keyboard handler, initializes mouse-related state, runs DDPCINTR and
   DDFLIPLY once, initializes video/menu data and enters `menu`.
2. `menu` (006B) loads `select.vga`, loads both high-score files (or uses
   compiled defaults), draws and animates the selector, polls INT 33h,
   and reacts to the INT 9 key bitmap.
3. `run_selection` (0BF0) sends F1-F8 to a table, F9 to
   `history_screen` (3140), and F10 to `options_screen` (142D).
4. The option screen loads `ddpcbkgd.vga`, `ddpcicon.spr` and the
   13-byte `C:\DELUXE\DDPCOPTN.BIN`. `load_options` (2BEB) supplies
   defaults when it is absent or not 13 bytes. `save_options` (2CFE)
   writes four choice bytes, four key words and one resolution byte, and
   mirrors them at DATA:31B8 on the menu side. The file is what persists
   the choices for the table programs. The menu writes it
   when the relevant option action saves changes, not unconditionally
   before every table EXEC.
5. The history viewer changes to `..\history`, loads `ddpchist.vga`,
   reads its picture/text resources and returns to the menu.
6. `exit` (003E) stops the sound driver, restores INT 9, returns to text
   mode, prints the selected status message and terminates through DOS.

## HISTORY data

The segment is not only renamed: its clear data is now named and its
near-pointer tables are `words` hints. It contains the `.016` picture
names, language directories, `.HOP`/`.IDX` files, intro modules, the
history font and VGA paths, and tables for 10 manufacturers, 29
designers, 22 years and 53 pinball-table names.

HISTORY:14AF holds 53 nine-byte table records. The filter code proves
fields +1 manufacturer, +2 year and +3 designer; +5 and +7 are offsets
of picture names. HISTORY:16CD is a five-word CODE dispatch table read at
CODE:32F2/330A: direct table selection, manufacturer/designer/year
filters, and leave. This made CODE:3599/35DC/361F/3662/36A4, plus their
shared helpers 3713 and 3BDC, reachable code rather than dead routines.

The named state includes the filter selections, loaded `.HOP` segment,
VESA bank state and filtered-record buffer at HISTORY:1730/1877-188B,
VBE information at 1A71/1B71, and the history text/scroll buffers at
1D18/1E26-1E2C.

## Starting a table and the other EXEC calls

All sites and operands were checked in the generated disassembly:

- `run_selection` uses DATA:134C: 0Ah calls F10 options; 9 calls F9
  history; 1..8 select BX=0 for PD or BX=1 for PD2. It restores INT 9,
  calls DDFLIPLY, installs INT 9 again, waits 46h frames, clears menu
  state and calls `run_table`.
- `run_table` (0B59) uses DATA:0D1D+2*BX to CHDIR to `..\DREAMS1` or
  `..\DREAMS2`, and DATA:0D19+2*BX to EXEC `PD.EXE` or `PD2.EXE` with
  the parameter block at DATA:133B. The command tail at DATA:1237 has
  length 1 and digit `0`..`3`; selections 5..8 have 4 subtracted. It
  CHDIRs to `..\deluxe` afterwards.
- `run_fli_player` (0C76) EXECs `ddfliply.exe` with the selection digit
  and CR. It is called before a selected table and once at startup with
  selection 0. Its `REP MOVSB` has CX=4 but SI is not initialized there;
  the length/digit/CR are overwritten afterwards and the fourth byte is
  unused, so the copy contributes nothing useful.
- `run_intro` (0CD0) EXECs `ddpcintr.exe` with `2` or `3`, selected by
  bit 0 read from PIT channel 1. T1 established that DDPCINTR treats the
  digit as a CD track, so this is presumably a pseudo-random choice
  between the two music tracks.
- `load_sound` (41E5/4345) reads `SOUND.CFG`, EXECs the named `.SDR`,
  and registers `sound_callback` (4421) through INT 66h AL=0Bh.

## Review round 1

1. DS for CODE:3158-31C8 is explicitly HISTORY. Its path offsets and
   state words therefore no longer acquire false DATA labels; DATA
   strings are no longer split. HISTORY also names the segment's actual
   use.
2. DATA:0D19 and 0D1D are word tables of two near DATA pointers, read by
   `run_table`; both have `words` hints.
3. CODE:43D7 is a `ptr` hint, so its PUSH is the address of
   `sound_callback`, used as ES:DX by INT 66h AL=0Bh.
4. The full table/FLI/intro EXEC flow and command tails are recorded
   above.
5. Every routine-like gap was decoded. HISTORY:16CD is a referenced
   five-word CODE table (reader at 32F2/330A), so it now reaches
   3662/3599/35DC/361F/36A4; 3713 and 3BDC follow from their calls.
   Full-image searches found no direct call/jump, immediate, pointer
   table, INT-vector, segment-zero vector write or INT 33h callback
   registration that reaches the remaining dead clusters. Those are
   026B, 0BD4, 0D1D, 0D3E, 0D91, 0DE1, 0EC1, 104A, 1056, 1149, 1414,
   1979, 3100, 3273/3274, 38F1, 3904, 4162/418C and 43D2. Internal calls
   within a dead cluster are noted in the hints.
6. CODE:1978 is a one-byte guard for live routine 1921. CODE:1979 is a
   separate, unreferenced pixel-copy routine. CODE:19CA-2BCA is data:
   two 24-by-48 word tables (at 19CA and 22CA), paired video/source
   offsets used by 1979 and by the live option drawer at 2DC8. Routine
   1921 shuffles the paired tables once.
7. Counts and the gap list below are the final values.

## Uncertainty / not verified

The program was not run: the runner does not support this menu program's
full path yet. Behaviour above is from code and DOS/BIOS/INT 66h
interfaces. The PIT-based intro choice is presumably random, and the
remaining dead-code classification means no reference mechanism present
in this image was found; it cannot prove what older source versions
intended.
